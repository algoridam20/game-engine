game-player-service Architecture HLD LLD Conventions

High-Level Design

Role

Owns player identity, WebAuthn passkeys, and JWT issuance/validation.

Consumed as a Spring Boot module (auto-config). Shared JWT types live in game-commons; other services validate player JWTs via PlayerJwtValidator.

Client ──► game-player-service ──► DB (players, player_passkeys)
                │
                ├── issues JWT (signup/login finish)
                └── validates JWT (filter) for /player/**
Other services ──► PlayerJwtValidator (game-commons contract)

Auth model

TokenTypeTTLPurpose
Ceremony (requestId) PCT (HS256) 5 min Bridge options → finish; holds challenge + signup context
Session JWT JWT (HS256) configurable Bearer auth for /player/**

Flow: options → ceremony token → client WebAuthn → finish → JWT.

Public (no JWT): /api/v1/auth/passkeys/signup/**, /api/v1/auth/passkeys/login/**
Authenticated: /api/v1/player/**

API

Base: /api/v1. Responses wrapped in GeneralResponse.

Sequences

Signup

sequenceDiagram
  participant C as Client
  participant S as PasskeyAuthService
  participant CT as CeremonyToken
  participant RP as WebAuthn RP
  participant DB as DB

  C->>S: POST signup/options (handle)
  S->>DB: existsByHandle?
  S->>CT: issueRegistration (challenge, playerId, handle…)
  S-->>C: requestId + creation options
  C->>C: navigator.credentials.create
  C->>S: POST signup/finish (requestId, credential)
  S->>CT: verifyRegistration
  S->>DB: save PlayerEntity
  S->>RP: registerCredential
  RP->>DB: save PlayerPasskeyEntity
  S-->>C: JWT

Login

sequenceDiagram
  participant C as Client
  participant S as PasskeyAuthService
  participant CT as CeremonyToken
  participant RP as WebAuthn RP
  participant DB as DB

  C->>S: POST login/options (handle?, gameId?)
  S->>CT: issueLogin (challenge, handle?, gameId?)
  S-->>C: requestId + request options
  C->>C: navigator.credentials.get
  C->>S: POST login/finish (requestId, credential)
  S->>CT: verifyLogin
  S->>RP: authenticate
  RP->>DB: load credential / update signature count
  S-->>C: JWT (optional gameId claim)

Authenticated request

sequenceDiagram
  participant C as Client
  participant F as JwtAuthenticationFilter
  participant P as CurrentPlayerProvider
  participant S as PasskeyAuthService

  C->>F: Authorization: Bearer JWT
  F->>F: validate → SecurityContext(PlayerJwtInfo)
  C->>S: GET /player/me
  S->>P: requirePlayer()
  P->>P: load PlayerEntity by JWT sub
  S-->>C: PlayerResponse
