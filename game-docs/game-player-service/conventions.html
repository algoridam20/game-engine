game-player-service HLD LLD Conventions Plan

Conventions

Packages

com.algoridam.games.player
  controller/   HTTP only — validate + delegate
  service/      business flows + ceremony tokens
  security/     JWT filter, keys, current player
  entity/       JPA tables
  repository/   Spring Data JPA
  dao/          WebAuthn repository adapters
  config/       security, passkey, CORS, auto-config
  dto/          request/response records

Naming

  • Entities: *Entity, tables plural (players, player_passkeys)
  • Repos: *Repository (domain JPA); DAOs: *Dao (framework adapter interfaces)
  • DTOs: nested records in PasskeyDtos
  • IDs: UUID v7 via UuidV7Generator on @PrePersist

Auth

  • Issue JWT only from signup/login finish (JwtService.generate)
  • Ceremony state = signed PCT in requestId, not server session
  • Validate JWT in filter; load player in provider — not in controller
  • Public paths only under /api/v1/auth/passkeys/{signup,login}/**
  • Handles: trim + lowercase before persist/lookup

Errors

  • Throw ServiceException + ErrorCode (from game-commons)
  • Map integrity violations to DUPLICATE_REQUEST
  • WebAuthn failures → PASSKEY_VERIFICATION_FAILED
  • Last passkey delete → CANNOT_DELETE_LAST_PASSKEY

game-commons vs this module

In commonsIn this service
PlayerJwtInfo, PlayerJwtValidator, InvalidPlayerJwtException JWT issue + concrete validator (JwtService)
BaseEntity, UuidV7Generator, GeneralResponse, ErrorCode, ServiceException Passkey/WebAuthn, entities, repos, filter, security config

Do not put WebAuthn or player tables in commons. Other services depend on the JWT contract only.
